# Reminder Super-App (Telegram Mini App)

Мини-приложение внутри Telegram: напоминания, финансы, КБЖУ, дневник + заготовка под ИИ-ассистента.

## Структура

```
reminder-app/
├── frontend/     # Telegram Mini App (React + Vite + Telegram WebApp SDK)
└── backend/      # Express API + Telegram Bot (Telegraf) + Prisma (SQLite/Postgres)
```

## Как это работает

1. Пользователь открывает бота в Telegram → жмёт кнопку "Открыть приложение" → открывается Mini App (frontend).
2. Frontend получает `initData` от Telegram WebApp SDK, backend проверяет подпись и авторизует пользователя по `telegram_id`.
3. Все данные (финансы, КБЖУ, дневник, напоминания) хранятся в БД, привязаны к `telegram_id`.
4. Напоминания рассылает бот (Telegraf) через `node-cron` — проверяет БД раз в минуту и шлёт сообщения в личку.
5. Голосовой ввод внутри Mini App — через Web Speech API / запись аудио и отправку на backend (заготовка, распознавание можно подключить позже — Whisper API и т.п.).
6. **iOS Back Tap → голосовое боту без разблокировки телефона**:
   - Настраивается через приложение "Быстрые команды" (Shortcuts), НЕ через код мини-аппа (Apple не даёт сторонним приложениям слушать Back Tap).
   - Сценарий А (просто): Shortcut на Back Tap → "Открыть URL" → `tg://resolve?domain=your_bot_username`. Открывает чат с ботом, дальше пользователь зажимает микрофон вручную.
   - Сценарий B (голосовое без открытия Telegram): Shortcut на Back Tap → "Диктовка текста" или "Запись аудио" → HTTP POST на `backend/voice-webhook` с файлом → backend через Bot API отправляет это как voice-сообщение пользователю в чат с ботом (или сразу расшифровывает и создаёт запись в дневнике/напоминание). Инструкция сборки такого Shortcut — в `backend/VOICE_SHORTCUT.md`.
7. **Расчёт нормы КБЖУ**: во вкладке "КБЖУ" при первом заходе пользователь вводит рост/вес/возраст/пол/уровень активности/цель (похудение/поддержание/набор). Backend (`backend/src/kbjuCalc.js`) считает базовый обмен по формуле Миффлина-Сан Жеора, умножает на коэффициент активности, корректирует под цель (±15%) и делит калории на БЖУ (30/25/45%). Дальше на вкладке показываются прогресс-бары "съедено / норма" на сегодня.

8. **Голос → ИИ → автораскладка по вкладкам** (готово, не заглушка):
   - На вкладке "Ассистент" — кнопка 🎤, запись идёт через `MediaRecorder`, аудио отправляется на `backend/api/assistant/process-audio`.
   - Backend: `services/transcribe.js` — распознаёт речь в текст через Whisper API (нужен `OPENAI_API_KEY`).
   - `services/classify.js` — отправляет текст в Claude API (`ANTHROPIC_API_KEY`), модель определяет тип (напоминание/трата/приём пищи/дневник) и извлекает структурированные поля строго в JSON.
   - `services/saveEntry.js` — сохраняет результат сразу в нужную таблицу БД.
   - Тот же пайплайн работает и через iOS Shortcut / Back Tap (`backend/src/routes/voiceWebhook.js`): человек говорит без разблокировки телефона → бот присылает в Telegram подтверждение вида "🎙 Распознано: ... → 💰 Расход записан: 500 ₽ (еда)".
   - Обязательно впиши `OPENAI_API_KEY` и `ANTHROPIC_API_KEY` в `.env`, иначе распознавание вернёт ошибку.

9. Место под текстовые вопросы к ассистенту по своим записям (аналитика "сколько я потратил на еду в этом месяце" и т.п.) пока заглушка — `backend/src/routes/assistant.js` (`/ask`).

## Масштабирование под большую аудиторию

Проект рассчитан на много одновременных пользователей, поэтому:

- **БД — PostgreSQL**, не SQLite (SQLite не выдержит параллельную запись от многих пользователей). Индексы уже добавлены на часто запрашиваемые поля (`userId`, `dueAt` и т.п.).
- **Бот работает через webhook**, а не long-polling — это позволяет запускать несколько инстансов backend без конфликтов. Нужно задать `PUBLIC_URL` в `.env` — HTTPS-адрес самого backend'а, куда Telegram будет стучаться.
- **Голосовой вебхук использует личный токен на каждого пользователя** (команда `/voicetoken` в боте), а не общий секрет — иначе один утёкший секрет скомпрометировал бы всех.
- **Rate limit на дорогие ИИ-эндпоинты** (`/api/assistant/process-audio` и `/voice-webhook`) — не больше 10 запросов в минуту с одного источника, т.к. каждый голосовой вызов стоит денег (Whisper + Claude API).
- **Рассылка напоминаний троттлится** — очередь с задержкой между сообщениями, чтобы не упереться в лимит Telegram (~30 сообщений/сек на бота). При дальнейшем росте рассылку стоит вынести в отдельный воркер-процесс, а `cron` в `bot.js` — заменить на что-то вроде BullMQ с Redis.

Дальнейшие шаги при росте: кэширование частых запросов (Redis), очередь задач для тяжёлых операций (обработка голоса — не блокировать HTTP-запрос, а отдавать результат через WebSocket/поллинг), горизонтальное масштабирование backend за балансировщиком нагрузки.

## Тарифы и пейволл на голосовые

- Каждый аккаунт получает **2 бесплатных голосовых навсегда** (не в день) — считается в `User.freeVoiceUsed`.
- Как только лимит исчерпан, а активной подписки нет — голосовое **не отправляется в Whisper/Claude вообще** (проверка в `services/voiceQuota.js` идёт до вызова ИИ), пользователю показываются тарифы вместо результата. Это защищает твой бюджет от бесплатных пользователей.
- Тарифы заданы в `backend/src/pricing.js` (единый источник правды, экономия считается автоматически от месячной цены):
  - 1 месяц — 305 ₽
  - 6 месяцев — 1350 ₽ (экономия 480 ₽ / 26%)
  - 12 месяцев — 2600 ₽ (экономия 1060 ₽ / 29%)
  - Навсегда — 5000 ₽ (экономия 2320 ₽ / 32% против эквивалента 24 месяцев, окупается через ~16 месяцев использования)
- Фронтенд: `frontend/src/tabs/PricingPlans.jsx` — карточки с зачёркнутой "обычной" ценой и итоговой ценой (в стиле скидочного баннера), встроены в вкладку "Ассистент" — показываются автоматически, когда бесплатные голосовые заканчиваются.
- `backend/src/routes/billing.js` — `/api/billing/plans` отдаёт тарифы с посчитанной экономией; `/api/billing/subscribe` — пока заглушка (нужно подключить платёжного провайдера через @BotFather → Payments, например ЮKassa, чтобы слать `sendInvoice` прямо в Telegram); `/api/billing/activate-dev` — временный ручной способ включить себе подписку для тестирования, пока оплата не подключена.

**Хостинг:**
- Backend на Fly.io (свободный лимит) или дешёвый VPS: **$0-5/мес**
- PostgreSQL на Neon (бесплатный тариф до 0.5 ГБ): **$0/мес**

**ИИ-обработка голоса** (самая переменная часть расходов):
- Whisper API (распознавание речи): **$0.006 за минуту** аудио
- Claude Haiku (классификация текста, `services/classify.js` уже переключён на самую дешёвую модель `claude-haiku-4-5-20251001`): доли цента за запрос — стоимость классификации в этом масштабе пренебрежимо мала по сравнению с Whisper
- При 250 пользователях, 3 голосовых/день по 15 сек = ~11 250 сообщений/мес × 0.25 мин = ~2 800 минут → **~$17/мес** на Whisper
- Установлен **дневной лимит 40 голосовых на пользователя** (`backend/src/services/voiceQuota.js`) — защита от неожиданного счёта, если кто-то начнёт злоупотреблять или один клиент зациклится
- Ограничен размер аудиофайла (3 МБ, ~2-3 минуты) — длинные голосовые не смогут разово взвинтить счёт

**Итого ожидаемо**: около **$20-30/мес** при 200-300 активных пользователях с умеренным использованием голоса. Основная переменная — сколько именно голосовых будут присылать пользователи; текстовый ввод (Web Speech API в браузере) в мини-аппе — **бесплатный**, т.к. распознавание идёт прямо в браузере пользователя, а не через Whisper.

**Дополнительно рекомендую:**
- Поставить Usage limits (лимит трат) на platform.openai.com и console.anthropic.com — на случай непредвиденного всплеска.
- Если бюджет совсем сжат — можно первое время оставить голосовой ввод только через встроенный в браузер Web Speech API (бесплатно), а серверную обработку голоса (Whisper+Claude, платную) включить только для iOS Shortcut-сценария, где без неё никак.

## Быстрый старт

```bash
# backend
cd backend
cp .env.example .env   # впиши BOT_TOKEN и т.д.
npm install
npx prisma migrate dev --name init
npm run dev

# frontend
cd frontend
npm install
npm run dev
```

Для локального теста Mini App нужен HTTPS-туннель (ngrok/cloudflared) — Telegram не открывает http:// адреса внутри WebApp.
